2. PROBLEMA INICIAL IDENTIFICADO
================================================================================

SÍNTOMA:
- API de Kobo devolvía solo 25 columnas
- CSV export de Kobo mostraba 34 columnas
- Faltaban columnas expandidas de campos select_multiple
- Solo se cargaban 25 columnas a Neon en vez de todas

DIAGNÓSTICO REALIZADO:

A) Diferencia API vs CSV Export:
   - API: Devuelve nombres INTERNOS (ej: "datos_per/cant_pers")
   - CSV: Usa LABELS bonitos (ej: "Cantidad de personas en situación de calle...")
   
B) Problema con select_multiple:
   El campo "caracteristicas_puntos/caracteristicas_observada" es tipo select_multiple
   con 7 opciones:
   
   1. Con estructura tipo carpa o refugio
   2. Colchón/es  
   3. Bolsos y/o bolsas
   4. No se observa nada de lo anterior
   5. Otro materiales acumulados (Cartón, chatarras, etc.)
   6. Silla de ruedas, carrito de bebé
   7. Carro para transportar cosas (Cartoneros)
   
   - API devuelve: Solo campo principal con valores "1 2 5" (valores seleccionados)
   - CSV export: Expande en 8 columnas (campo base + 7 opciones con labels bonitos)

C) Filtro de columnas:
   - reclassify_sheet_once.py tenía lista "columnas_deseadas" que filtraba a solo 25
   - Esto excluía las columnas expandidas del select_multiple

3. ESTRUCTURA DEL FORMULARIO KOBO ACTUAL
================================================================================

Según el schema obtenido del API (asset_info.json):

CAMPOS REALES DEL FORMULARIO (6 preguntas):

1. geo_ref/geo_punto (geopoint)
   → Se expande en: latitude, longitude, altitude, precision

2. datos_per/dni_operador (integer)
   → "Ingrese número de documento del usuario que completa el formulario"

3. datos_per/cant_pers (integer)
   → "Cantidad de personas en situación de calle observadas"

4. datos_per/sit_calle (select_one con 6 opciones)
   → "La/s persona/s esta/n"
   Opciones: Durmiendo, Cocinando/Comiendo, Circulando, Mendigando, Vendiendo, Recolectando

5. caracteristicas_puntos/caracteristicas_observada (select_multiple con 7 opciones)
   → "En el lugar hay…"
   Se expande en 8 columnas (principal + 7 opciones)

6. caracteristicas_puntos/NNyA_observa (select_one dicotómico)
   → "Se observan niños/as en el lugar"
   Opciones: Sí, No

METADATOS AUTOMÁTICOS:
- start, end, today, username, deviceid
- _id, _uuid, _submission_time, _status, _submitted_by, __version__, _tags, _notes, etc.

TOTAL ESPERADO: ~32-34 columnas (dependiendo de metadatos y expansiones)

4. SOLUCIONES IMPLEMENTADAS
================================================================================

A) MAIN_ACT_FLASH.PY (Extracción desde API → Neon)
---------------------------------------------------

FUNCIONES NUEVAS AGREGADAS (líneas 65-195):

1. obtener_schema_kobo()
   - Obtiene estructura del formulario desde API v2/assets/{uid}/
   - Retorna content.survey y content.choices

2. expandir_geopoint(df, geopoint_col)
   - Recibe columna con formato "lat lon alt precision"
   - Crea 4 columnas: latitude, longitude, altitude, precision
   - Elimina columna original de geopoint

3. expandir_select_multiple(df, schema, col_name)
   - Detecta campos select_multiple en el schema
   - Busca las opciones (choices) correspondientes
   - Crea columna booleana por cada opción
   - Formato: "campo_principal/opcion_name"

4. asegurar_columnas_schema(df, schema)
   - Itera sobre todas las preguntas del schema
   - Asegura que existan columnas para cada campo
   - Para select_multiple, busca columnas expandidas
   - Crea columnas vacías (False/NaN) si faltan

5. extraer_kobo_completo()
   - FUNCIÓN PRINCIPAL que integra todo
   - Pasos:
     a. Obtener schema del formulario
     b. Descargar datos via API data.json
     c. Normalizar JSON con pd.json_normalize()
     d. Expandir geopoints
     e. Expandir select_multiple
     f. Asegurar todas las columnas del schema
     g. Retornar DataFrame completo

CAMBIO EN EJECUCIÓN PRINCIPAL (línea 462-478):
   ANTES: df_raw = pd.json_normalize(resp.json()['results'])
   AHORA: df_raw = extraer_kobo_completo()
